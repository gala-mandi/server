# Galla Mandi — server

REST API for Galla Mandi, built with NestJS, PostgreSQL and Drizzle ORM. It is the only part of the system that talks to the database.

## Requirements

- Node.js 24 (see `.nvmrc`; 22.12+ also works)
- npm
- Docker with Docker Compose

## Setup

```bash
git clone git@github.com:gala-mandi/server.git
cd server
cp .env.example .env          # then change POSTGRES_PASSWORD and DATABASE_URL
npm install
docker compose up -d          # starts Postgres
npm run db:migrate            # creates the tables
npm run dev                   # API on http://localhost:4000
```

- Health check: <http://localhost:4000/health>
- API docs (Swagger): <http://localhost:4000/docs>

If port 5432 is already used on your machine, set `POSTGRES_PORT` in `.env` (for example `55432`) and use the same port in `DATABASE_URL`.

## Environment variables

Every variable is listed in `.env.example`. They are checked with Zod when the app starts. A missing or wrong value stops the app with a message that names each bad variable, for example:

```
Error: Invalid environment variables:
  - DATABASE_URL: Invalid input: expected string, received undefined
```

Never commit `.env`.

## Scripts

| Script                                    | What it does                                                                      |
| ----------------------------------------- | --------------------------------------------------------------------------------- |
| `npm run dev`                             | Start the API in watch mode                                                       |
| `npm run build`                           | Compile to `dist/`                                                                |
| `npm run lint` / `npm run lint:fix`       | ESLint                                                                            |
| `npm run format` / `npm run format:check` | Prettier                                                                          |
| `npm run typecheck`                       | TypeScript, no output                                                             |
| `npm test`                                | Unit tests (Jest)                                                                 |
| `npm run test:e2e`                        | Integration + e2e tests (Jest + supertest) against the Postgres in `DATABASE_URL` |
| `npm run db:generate`                     | Generate a migration from the Drizzle schema                                      |
| `npm run db:migrate`                      | Apply migrations                                                                  |

A Husky pre-commit hook runs ESLint and Prettier on staged files (lint-staged). CI (`.github/workflows/ci.yml`) runs lint, format check, type-check, unit tests, migrations, e2e tests and the build on every pull request.

## Project layout

```
src/
  modules/<feature>/      controller, service, dto, tests
  common/                 guards, decorators, filters, interceptors
  database/schema/        one Drizzle file per table (matches docs/database/schema.dbml)
  database/migrations/    generated by drizzle-kit, never edited after merge
  config/                 Zod env schema
test/                     integration and e2e tests
```

## What is set up

- **Config:** `@nestjs/config` + Zod (`src/config/env.schema.ts`)
- **Database:** global `DatabaseModule` gives a Drizzle instance (`@Inject(DRIZZLE)`). First migration creates `tenants` and `users`.
- **Validation:** global `ZodValidationPipe` (nestjs-zod). DTOs are Zod schemas.
- **Errors:** every error is JSON `{ statusCode, message, errors? }`. Validation errors list `errors: [{ field, message }]`. Stack traces are logged, never returned.
- **Security:** helmet, CORS allow-list (`CORS_ORIGINS`), rate limit with `@nestjs/throttler` (`THROTTLE_LIMIT` per `THROTTLE_TTL_MS`, `429` when over).
- **Logs:** nestjs-pino (JSON). `Authorization` and `Cookie` headers are redacted.
- **Docs:** Swagger UI at `/docs`, OpenAPI JSON at `/docs-json`.

## Database changes

1. Edit or add a file in `src/database/schema/`. Table and column names must match `docs/database/schema.dbml`.
2. Run `npm run db:generate` and commit the new migration.
3. Run `npm run db:migrate`.

Never edit a migration that is already merged.
